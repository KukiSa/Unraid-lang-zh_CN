:tips_tweaks_general_plug:
> 一般建议：
>
> + 某些情况下使用静态 IP 地址会有所帮助。NFS 共享通过 IP 地址引用，请在路由器中保留该地址，或选择地址段中较高的地址以避免冲突。
> + 不建议使用巨帧 (Jumbo Frames)，已知它可能导致某些 Docker 容器出现问题。
> + 除非 Unraid 服务器配有 UPS，否则不要将 vm.dirty_ratio 设为超过 20%。停电时，尚未写入磁盘的数据可能丢失。
> + 除非两个值都小于 10，否则不建议将 vm.dirty_background_ratio 设为超过 vm.dirty_ratio 的一半。
:end

:tips_tweaks_nic_flow_control_plug:
> 设为「是」可禁用网卡流量控制 (Flow Control)。此功能最初用于混合速率设备的网络，在现代网络中未必仍有必要。
> 网管交换机通常可以自行开关流量控制，消费级交换机一般没有这种控制能力。
> 某些情况下流量控制会导致网络问题。如果遇到网络异常，插件建议尝试禁用。
>
> 从其他设置切换回「默认」需要重启。
:end

:tips_tweaks_nic_offload_plug:
> 设为「是」可禁用网卡卸载 (Offload)。此功能将部分网络处理及大数据包处理从主 CPU 转交网卡，以降低 CPU 负载并提高吞吐量。
> 某些情况下，TSO 卸载会导致网络问题。如果遇到网络异常，插件建议尝试禁用网卡卸载。
>
> 从其他设置切换回「默认」需要重启。
:end

:tips_tweaks_rx_buffer_plug:
> 选择网卡接收环形缓冲区 (Rx Ring Buffer) 大小。部分网卡对此大小有限制，建议使用默认值 256。
>
> 从其他设置切换回「默认」需要重启。
:end

:tips_tweaks_tx_buffer_plug:
> 选择网卡发送环形缓冲区 (Tx Ring Buffer) 大小。部分网卡对此大小有限制，建议使用默认值 256。
>
> 从其他设置切换回「默认」需要重启。
:end

:tips_tweaks_nics_plug:
> 以逗号分隔需要应用上述设置的网卡。若多个网卡组成链路聚合 (Bonding)，请包含所有成员。流量控制、TSO 和网卡缓冲区设置将应用于这些网卡。
:end

:tips_tweaks_dirty_background_plug:
> 插件建议将 vm.dirty_background_ratio 设为 3%，vm.dirty_ratio 设为 5%。
> 内存较大时，可分别设为 1% 和 2%。
> 注意：除非 UPS 能可靠地关闭 Unraid，否则不要将这些值增大至超过默认设置。
>
> vm.dirty_background_ratio 是占总内存的百分比。除非内存很大，否则建议保留 3%。运行媒体流或游戏虚拟机时，可使用 1%。
:end

:tips_tweaks_dirty_ratio_plug:
> vm.dirty_ratio 是占总内存的百分比。
> 设得过高可能导致 Linux 终止某些进程以释放内存。除非内存很大，否则建议使用默认值 5%。
:end

:tips_tweaks_cpu_governor_plug:
> 选择常规运行时使用的 CPU 调速策略 (Governor)。
>
> + **节能 (Power Save)**：将 CPU 固定在最低频率，最大限度节能。
> + **按需 (On Demand)**：ACPI CPUFreq 驱动的默认策略，根据负载调整频率，变化较积极。
> + **保守 (Conservative)**：根据负载平缓调整频率，可能增加延迟。
> + **性能 (Performance)**：无论负载如何，都将 CPU 固定在最高频率，可改善性能和延迟。
> + **Schedutil**：由 Linux 调度器根据负载调整 CPU 频率。
>
> 也可以使用 rc.tweaks 脚本设置策略，命令为：
> /usr/local/sbin/rc.tweaks set_governor 'governor'
> governor 可选值为：'ondemand'、'performance'、'powersave'、'conservative' 和 'schedutil'。
:end

:tips_tweaks_power_save_cpu_governor_plug:
> 选择节能时使用的 CPU 调速策略 (Governor)。
>
> + **节能 (Power Save)**：将 CPU 固定在最低频率，最大限度节能。
> + **按需 (On Demand)**：ACPI CPUFreq 驱动的默认策略，根据负载调整频率，变化较积极。
> + **保守 (Conservative)**：根据负载平缓调整频率，可能增加延迟。
> + **Schedutil**：由 Linux 调度器根据负载调整 CPU 频率。
:end
