**彩色状态指示器**：*阵列设备 (Array Devices)* 各行开头的颜色含义如下：

<i class='fa fa-circle orb green-orb'></i>运行正常，设备处于活动状态。

<i class='fa fa-circle orb grey-orb'></i>设备处于待机（停转）状态。

<i class='fa fa-warning orb yellow-orb'></i>设备内容由阵列 (Array) 模拟提供 (Emulated)。

<i class='fa fa-times orb red-orb'></i>设备已禁用，内容由阵列模拟提供。

<i class='fa fa-square orb blue-orb'></i>新设备。

**设备标识**是唯一识别存储设备的*签名*，包括设备型号、序列号、Linux 设备 ID 和容量。

**温度**直接从设备读取。可在[显示设置](Settings/DisplaySettings)中选择单位。不读取已停转硬盘的温度，因为读取通常会将其唤醒，此时显示 `*`。SSD 和闪存设备也可能显示 `*`；有些设备会返回有效温度，有些则返回 `0`。

**大小、已用、可用**分别表示设备总容量、已用空间和剩余文件存储空间。单位也在[显示设置](Settings/DisplaySettings)中配置。由于文件系统本身占用空间，空磁盘的已用空间也不为零。

*注意：对于多设备缓存存储池 (Cache Pool)，这些数值是 btrfs 返回的整个存储池 (Pool) 的数据。*

**读取、写入**是发送给设备 I/O 驱动的请求次数，可随时清空，参阅下方「阵列状态」。

**错误**统计设备 I/O 驱动报告的*不可恢复*错误。阵列发生不可恢复读取错误时，会利用奇偶校验 (Parity) 即时重建缺失数据，并尝试写回失败扇区。任何不可恢复的写入错误都会使磁盘被*禁用*。

**文件系统 (FS)** 表示设备第 1 分区中检测到的文件系统。

**查看**列中的文件夹图标表示设备已*挂载*，点击可浏览文件系统。

在[显示设置](Settings/DisplaySettings)中启用「显示阵列汇总」后，会增加**总计**行，汇总设备统计数据，包括平均温度。

必须停止阵列才能更改阵列设备分配。

Unraid 阵列包含一块或两块奇偶校验盘 (Parity Disk) 和若干数据盘 (Data Disk)。数据盘存储用户数据，奇偶校验盘提供磁盘故障恢复所需的冗余信息。

由于数据不跨阵列进行条带化，奇偶校验盘容量必须不小于最大的数据盘，也应尽量选用性能最好的驱动器。

每个数据盘有独立文件系统，可以单独导出为共享。

点击设备名称可配置该设备的设置，并运行相关工具。

**彩色状态指示器**：*存储池设备 (Pool Devices)* 各行开头的颜色含义如下：

<i class='fa fa-circle orb green-orb'></i>运行正常，设备处于活动状态。

**存储池设备**是 Unraid 阵列 (Array)*之外*的单个设备或多个设备组成的池，也可像阵列设备 (Array Devices) 一样导出供网络访问。由于不属于 Unraid 阵列，写入速度显著更快。

可以使用两种配置：

1. 单个设备；
2. 多设备存储池 (Pool)。

单设备配置可以格式化为所支持的文件系统（btrfs、reiserfs 或 xfs）。此配置性能最高，但没有冗余保护；设备故障时，上面的全部数据可能丢失。

多设备配置会自动为数据和元数据选择 *btrfs-raid1*。btrfs 允许向池中加入多个设备，并确保每份数据副本写入两个不同设备，因此可以承受单盘故障而不丢失数据。

启用[用户共享 (User Share)](/Settings/ShareSettings)后，可配置共享自动使用存储池来加速写入。名为 *Mover* 的后台进程可按计划定期将用户共享文件从缓存移至阵列。
:end

:array_devices_help:
#### 分配设备

Unraid 磁盘阵列 (Array) 包含若干数据盘和最多两块奇偶校验盘 (Parity Disk)。数据盘存储用户数据；一块或两块奇偶校验盘分别提供从单盘或双盘故障中恢复所需的冗余信息。

此处的*磁盘 (Disk)* 指阵列中的逻辑存储位置，*硬盘 / 驱动器 (Drive)* 指实际 HDD 硬件。之所以区分，是因为即使对应硬盘被禁用或缺失，阵列仍可模拟该磁盘并进行读写。因此，可以分别询问「哪个设备被分配为奇偶校验盘」或「哪个设备对应 disk2」。

需要将实际硬盘分配给阵列磁盘。阵列停止后，可在主界面操作。每个阵列磁盘都有下拉框，列出所有未分配设备，选择所需设备即可。每次更改分配时，系统都会更新配置文件记录。

#### 要求

传统 RAID 跨多个设备条带化存储数据，而 Unraid 将文件保存在独立硬盘上。因此，写入文件时会同时涉及目标数据盘和奇偶校验盘。为此：

* 奇偶校验盘容量必须不小于任何数据盘；

并且：

* 如有选择，应使用性能最快的磁盘作为奇偶校验盘。

#### 配置步骤

1. 决定哪块硬盘用于奇偶校验 (Parity)，哪些用于数据盘 disk1、disk2 等，并做好标记。记录每块硬盘的序列号，稍后分配时需要使用。

2. 安装硬盘、启动服务器并打开 WebGUI。全新系统的主界面会显示尚未安装磁盘，这并不表示系统检测不到硬盘，只表示还没有分配设备。

3. 根据第 1 步记录的序列号，从奇偶校验盘和各数据盘的下拉列表中选择正确硬盘。

#### 热插拔

硬件支持时，也可*热插拔*硬盘。例如使用支持热插拔的硬盘笼时，可以在服务器通电且阵列已停止的情况下插入硬盘。刷新主界面后，新设备会出现在未分配设备下拉列表中。

#### 后续操作

分配完所有硬盘后，请参阅下方「阵列状态」并启动阵列。
:end

:encryption_help:
#### 加密信息输入

阵列 (Array) 停止时可以指定新加密密钥。设备使用某个密钥格式化后，只能用同一密钥解锁。此处更换加密密钥需要重新格式化加密设备，**会永久丢失这些设备上的所有现有数据。**

#### 密码短语 (Passphrase)

输入最多 512 个字符的密码短语。强烈建议只使用 [ASCII 表](https://en.wikipedia.org/wiki/ASCII)前 128 个字符中的 95 个可打印字符，因为其二进制表示保持一致。其他字符可能随系统配置使用不同编码，编码改变后密码短语便无法使用。需要更长密码短语或二进制数据时，请上传密钥文件。

安全密码短语的要求请参阅 [cryptsetup FAQ](https://gitlab.com/cryptsetup/cryptsetup/wikis/FrequentlyAskedQuestions#5-security-aspects)。

请**牢记**密码短语。**一旦丢失，加密内容将无法恢复！**

#### 密钥文件 (Keyfile)

选择本地保存的加密密钥文件或二进制文件，最大为 8M（8388608 字节）。

请**备份**本地密钥文件。**一旦丢失，加密内容将无法恢复！**
:end

:info_btrfs_balance_help:
**平衡 (Balance)** 运行 *btrfs balance*，在所有存储池设备 (Pool Devices) 间重新分布区段 (Extents)，例如将存储池 (Pool) 从 raid1 转为 raid0，或反向转换。

*完整平衡*基本上会重写当前文件系统中的全部内容。

*模式转换*影响 btrfs 数据区段；此处元数据始终使用 raid1，任何平衡操作都会在必要时将其转换为 raid1。

根据文件系统大小和设备速度，运行可能耗时很长。

Unraid OS 创建多设备存储池时使用以下默认选项：

`-dconvert=raid1 -mconvert=raid1`

完整说明请参阅 btrfs-balance [手册页](https://man7.org/linux/man-pages/man8/btrfs-balance.8.html)。

*注意：Linux 社区通常仍将 raid5 和 raid6 视为**实验性**功能。*
:end

:share_edit_allocation_method_help:
此设置决定 Unraid OS 创建新文件或目录时如何选择磁盘。

**高水位 (High-water)**
从可用空间仍高于当前*水位线*的磁盘中，选择编号最小的磁盘。初始水位线为最大数据盘容量的一半。若所有磁盘的可用空间均不高于当前水位线，则将水位线减半，再次选择。

**高水位**旨在尽可能多地向每个磁盘连续写入，以减少唤醒磁盘的次数，同时尽量使各磁盘保留相近的可用空间，将数据均衡分布在阵列 (Array) 中。

**依次填满 (Fill-up)**
选择可用空间仍高于**最小可用空间**设置值、且编号最小的磁盘。

**最多空闲空间 (Most-free)**
选择当前可用空间最多的磁盘。
:end

:share_edit_split_level_help:
决定是否允许目录跨多个磁盘扩展，即拆分级别 (Split Level)。

**按需自动拆分任意层级的目录**
创建新文件或子目录时，Unraid OS 先按*分配方法 (Allocation Method)*选择目标磁盘。若目标磁盘上不存在其父目录，会先创建所需的各级父目录，再创建文件或子目录。

**按需仅自动拆分顶层目录**
在共享的一级子目录内创建文件或子目录时，如果目标磁盘上不存在该一级子目录，会先创建它。
如果在二级或更深层目录中创建，则新内容必须放在其父目录所在的同一磁盘上。

**按需仅自动拆分前 N 级目录**
与上述方式类似：如果父目录位于第 N 级，且目标磁盘上不存在该目录，系统会先创建所需父目录。若父目录深于第 N 级，则新内容只能创建在父目录已存在的磁盘上。

**手动：不自动拆分目录**
创建新文件或子目录时，只考虑已经存在其父目录的磁盘。
:end

:share_edit_cache_pool_help:
指定写入共享的新文件和目录是否可以写入缓存磁盘 / 存储池 (Pool) （如有）。此设置也影响 *Mover* 的行为。

**否 (No)**：禁止将新文件和子目录写入缓存。Mover 不执行操作，已在缓存上的此共享文件会留在原处。

**是 (Yes)**：缓存空间足够时，新文件和子目录写入缓存；空间不足时则写入阵列 (Array)。运行 Mover 时，文件和子目录从缓存移至阵列。

**仅使用 (Only)**：所有新文件和子目录必须写入缓存。缓存空间不足时，*创建*操作会因*空间不足*而失败。Mover 不执行操作，已在阵列上的文件会留在原处。

**优先使用 (Prefer)**：缓存空间足够时，新文件和子目录写入缓存；空间不足时写入阵列。运行 Mover 时，文件和子目录从阵列移至缓存。

**注意**：Mover 不会移动正在使用的文件。要移动 Docker 或虚拟机等系统服务使用的文件，必须在 Mover 运行期间禁用这些服务。
:end

:smb_case_sensitive_names_help:
控制文件名是否区分大小写。

默认值**自动**允许支持大小写敏感文件名的客户端 (Linux CIFSVFS) 逐个数据包告知 Samba，按 UNIX 大小写敏感语义访问文件系统。
Windows 客户端通常不使用这种语义，因此「自动」对其相当于「否」，但仍保留 Windows 传入的文件名大小写。目录很大时，Samba 需要搜索并匹配名称，可能降低性能。

设为**是**，文件按客户端传入的大小写创建，访问时也必须完全匹配。这可加快大目录访问，但某些 Windows 应用可能异常。例如，创建 MyFile 后，应用尝试打开 MYFILE，就会找不到文件。

**强制小写**会将所有客户端传入的文件名（不只是新文件名）转换为小写。无论 Windows 端如何混合大小写，存储和访问时都使用小写。这可确保应用不受大小写影响而找到文件，但目录列表不再保留原大小写。
注意：此设置只应为新共享配置。
:end

:mgmt_use_ssl_tls_help:
决定 WebGUI 在局域网中如何响应 HTTP 和 HTTPS 请求。

选择**否**，使用 HTTP，通过以下地址访问：

`http://<server-name>.<localTLD>`

或：

`http://<server-ip-address>`

选择**是**，启用自动生成的自签名 SSL 证书，通过以下地址访问：

`https://<server-name>.<localTLD>`

自签名证书会触发浏览器警告。

选择**严格 (Strict)**，*仅*使用 myunraid.net SSL 证书进行 HTTPS 访问（参阅下方**签发**）。此模式必须能访问 DNS 服务器。

**重定向**：访问 `http://<server-ip-address>` 或 `http://<server-name>.<localTLD>` 时，行为取决于「使用 SSL/TLS」：

* **严格**：重定向至 `https://<lan-ip>.<hash>.myunraid.net`。
* **是**：重定向至 `https://<server-ip-address> or https://<server-name>.<localTLD>` 中的对应地址。
* **否**：直接加载 HTTP 地址。

重要：路由器或上游 DNS 服务器启用 [DNS 重绑定保护](https://en.wikipedia.org/wiki/DNS_rebinding)时，可能无法选择**严格**。此保护会阻止 DNS 解析到私有 IP 地址范围，旨在保护局域网中 Web 界面存在缺陷或不安全的旧设备。

限制可能来自运营商 DNS，此时可更换为允许关闭重绑定保护的 DNS 服务，例如 OpenDNS。

更常见的情况是路由器启用了重绑定保护。多数消费级路由器没有此功能；如有，一般可在设置中关闭。

较高端路由器通常默认启用，可完全关闭，也可按域名放行。例如：

**DD-WRT**：使用 dnsmasq 且开启重绑定保护时，可在路由器配置中添加：

`rebind-domain-ok=/myunraid.net/`

**pfSense**：使用内置 DNS 解析服务时，可在自定义选项中添加：

`server:`<br>
`private-domain: "myunraid.net"`

**Ubiquiti USG**：可添加：

`set service dns forwarding options rebind-domain-ok=/myunraid.net/`

**OpenDNS**：前往 Settings → Security，*取消勾选*「Suspicious Responses - Block internal IP addresses」。此项只能整体开关，不能按域名放行。

其他方法均无效时，可尝试在计算机的 *hosts* 文件中添加记录，覆盖外部 DNS，将服务器的 myunraid.net 完全限定域名直接解析为本地 IP 地址。
:end

:mgmt_certificate_expiration_help:
**签发**可从 [Let’s Encrypt](https://letsencrypt.org/) 安装*免费*的 myunraid.net SSL 证书。

此证书有两种用途。首先，安装后，服务器可响应以下形式的备用 URL：

`https://<lan-ip>.<hash>.myunraid.net`

`<hash>` 是此服务器专属的 40 位十六进制字符串（160 位）。Lime Technology DDNS 服务器会将此地址解析为 `<lan-ip>`。证书主体设为 `*.<hash>.myunraid.net`，从而验证 HTTPS 连接。

将**使用 SSL/TLS**设为**严格**，可在局域网中仅使用此 URL。

第二个用途是启用 Unraid Connect 插件提供的安全远程访问。远程使用安全连接、本地使用非安全连接的组合也受支持。

安装 myunraid.net SSL 证书后，会启用后台服务：

- *renewcert*：服务器重启完成 60 秒后，联系 Lime Technology 证书续期服务，检查是否需要续期；此后每 24 小时检查一次。距到期不足 30 天时，会自动签发新证书并下载到服务器。

**删除**可移除 myunraid.net 证书文件。

**nginx 证书处理细节**

nginx 使用 USB 启动闪存设备上的两个证书文件：<br>

- 自签名证书：`config/ssl/certs/<server-name>_unraid_bundle.pem`
- myunraid.net 证书：`config/ssl/certs/certificate_bundle.pem`

nginx 启动时会自动创建自签名证书；服务器主机名或本地域后缀更改时会重新创建。

**nginx OCSP 装订支持**

证书中包含 OCSP 响应服务器 URL 时，会自动启用 OCSP 装订 (OCSP Stapling)。
因此，自签名证书不启用装订，符合条件的 CA 签名证书会启用。
:end

:nfs_tunable_fuse_remember_help:
启用 NFS 后，可通过此参数缓解或解决客户端遇到的「NFS 文件句柄失效 (Stale File Handle)」问题。

fuse_remember 控制内部 FUSE 子系统缓存用户共享 (User Share) 文件和目录信息的时间。NFS 客户端访问的文件或目录名称不在缓存中时，就可能遇到句柄失效。

数值单位为秒，默认 330，即 5 分半钟。另有两个特殊值：

* 0：完全不缓存文件或目录名称。
* -1：永久缓存，直到阵列 (Array) 停止。

仅使用 NFS 磁盘共享 (Disk Share)、不使用用户共享时，适合设为 0。

其他超时值都无法解决客户端句柄失效时，可考虑 -1。请注意，每缓存一个文件或目录名称约增加 108 字节内存占用。根据服务器内存和 NFS 访问的文件数量，可能导致内存不足。
:end

:eth_bonding_mode_help:
**模式 0 (balance-rr)**<br>
按顺序轮流通过各成员接口发送数据包。例如有两个成员接口时，第一个包由第一个接口发送，第二个包由第二个接口发送，第三个包再由第一个接口发送，依此类推。提供负载均衡和容错。

**模式 1 (active-backup)，默认**<br>
一个接口工作，其他接口处于备用状态。只有活动接口链路失效时，备用接口才接管。同一时刻只有一个成员处于活动状态，提供容错。

**模式 2 (balance-xor)**<br>
根据异或公式选择发送接口：源 MAC 地址与目标 MAC 地址异或，再对成员数量取模。对同一目标 MAC 始终选择同一成员，提供负载均衡和容错。

**模式 3 (broadcast)**<br>
所有成员接口都发送全部数据。使用较少，仅适合特定用途，只提供容错。

**模式 4 (802.3ad)**<br>
也称*动态链路聚合 (Bonding)*，将速率和双工设置相同的接口组成聚合组，需要交换机支持 IEEE 802.3ad。
发送接口由发送哈希策略决定，可通过 xmit_hash_policy 更改默认的简单异或策略。
并非所有发送策略都符合 802.3ad，尤其是该标准 43.2.4 节关于数据包乱序的要求；不同对端实现对不合规行为的容忍程度不同。

**模式 5 (balance-tlb)**<br>
称为*自适应发送负载均衡*。按各成员的当前负载和队列分配出站流量，入站流量由当前活动成员接收。

**模式 6 (balance-alb)**<br>
称为*自适应负载均衡*，在 balance-tlb 基础上增加 IPv4 接收负载均衡 (RLB)。
通过 ARP 协商实现：聚合驱动拦截服务器发出的 ARP 响应，将源硬件地址改为某个成员的唯一硬件地址，使不同客户端使用不同硬件地址访问同一服务器。

*建议使用模式 1 (active-backup)。其他模式适用于特定环境，可能需要交换机正确支持；选择不受支持的模式可能中断通信。*
:end

:apc_ups_type_help:
选择与实际设备对应的 *UPS 类型*，详情参阅描述。

+ **USB**：大多数新款 UPS 使用 USB。
+ **APCsmart**：较新的串行字符设备，适用于通过串口而非 USB 连接的 SmartUPS。
+ **Net**：通过 apcupsd 网络信息服务器连接主 apcupsd。适用于给本机供电、但连接到另一台计算机进行监控的 UPS。
+ **SNMP**：通过 SNMP 网络连接支持 SNMP 的 UPS。
+ **Dumb**：用于简单信号式 UPS 的旧串行字符设备。
+ **PCnet**：PowerChute Network Shutdown 协议，可搭配 AP9617 系列智能插槽卡，作为 SNMP 的替代方案。
+ **ModBus**：用于支持 MODBUS 协议的新款 SmartUPS 的串行设备。

:apc_ups_device_help:
按实际情况填写*设备*，仅在 *UPS 类型*不是 USB 时适用。

+ **apcsmart**：/dev/tty**
+ **net**：hostname:port。hostname 为 NIS 服务器 IP 地址，默认端口 3551。
+ **snmp**：hostname:port:vendor:community。hostname 为 UPS 的 IP 地址或主机名。vendor 可为 APC 或 APC_NOTRAP；后者禁用 SNMP trap 接收，通常应选 APC。端口通常为 161，community 通常为 private。
+ **dumb**：/dev/tty**
+ **pcnet**：ipaddr:username:passphrase:port。ipaddr 为 UPS 管理卡 IP 地址；username 和 passphrase 为卡上配置的凭据；port 为接收 UPS 消息的端口，通常为 3052。省略或留空时使用 3052。
+ **modbus**：/dev/tty**
:end
